# Agent Note: 移动端 Web 布局保留完整会话宽度

Status: implemented

[English](2026-08-21-mobile-web-layout.md) | 中文

## Problem

AppFrame 在 1024px 以下会把侧边栏收缩为常驻的 56px 控制栏。因此，390px 的手机在渲染聊天内容前就损失了超过七分之一的会话宽度。打开侧边栏会恢复 280px 的行内栏位，只给会话区留下 110px，使标题、控件与输入框碎裂成狭长条。设置面板进一步放大了问题：188px 的桌面导航轨道仍与内容并排，而面板本身受手机 viewport 限制，当前设置页窄到无法正常显示句子和控件。

窄屏状态并非单纯的间距缺陷。侧边栏、会话区和详情栏都是带本地查看状态的已挂载 slot 所有者，Settings 又是侧边栏中使用固定定位的后代。若移动端方案卸载某一栏，或对其祖先使用 transform，只会修好一张截图，却破坏状态保留，或把 Settings 遮罩限制在抽屉内部。

## Decision

AppFrame 测量自身框架，并在 720px 以下使用专门的手机展示。会话 grid 轨道占满整个框架；仍保持挂载的详情轨道在关闭时解析为零，打开时则接管整个框架；仍保持挂载的侧边栏变为画布外抽屉。抽屉最大宽度为 340px，并至少留下 24px 框架边缘供用户点击关闭。手机上，该 slot 始终收到宽版 owner 形状，而已存储的桌面侧边栏宽度偏好不受影响。

抽屉通过 `left` 而非 `transform` 过渡，因此固定定位后代仍以 viewport 为包含块。44px 的菜单控件负责打开；背景遮罩、Escape、侧边栏收起控件以及选择 Session 都会关闭抽屉。关闭的抽屉为 inert，并从无障碍树中隐藏。打开时焦点移入抽屉，并把会话区和详情栏设为 inert；关闭时焦点返回菜单控件。展开 Workspace 分组、搜索和查看选项会保持抽屉打开，因为这些操作是在准备导航，而不是选择目的地。

Settings 外壳在 640px 以下从桌面两栏面板切换为感知安全区的全高面板。分区导航变成可横向滚动的标签行，标题栏操作单独占一行，关闭命中区增大到 40px，只有当前分区纵向滚动。会话界面消费 AppFrame 的移动端变量，以获得 64px 标题栏避让、更紧凑的 transcript 与输入框内缩、安全区底部内边距、可横向滚动的标签，以及更大的输入工具栏命中区。

720–1023px 布局继续使用紧凑控制栏及其既有的[控制栏搜索手势保护](2026-08-18-rail-search-outside-click-self-dismissal.zh.md)；桌面让步和拖动行为保持不变。

## Alternatives considered

**保留 56px 控制栏并在行内展开。** 否决，因为控制栏会永久占用最小 viewport，而行内展开会让手机宽度下的会话区无法使用。

**用 `transform` 为抽屉制作动画。** 否决，因为变换后的侧边栏会成为其固定定位后代的包含块；Settings 遮罩会被裁到抽屉内部，而不是覆盖整个 viewport。

**在手机上卸载侧边栏与详情内容。** 否决，因为 slot 身份与本地状态必须在关闭和重新打开后继续存在。手机展示只改变几何和交互，不卸载这两个子树。

**只使用 window 媒体查询。** AppFrame 不采用该方案，因为外壳可能嵌入比浏览器窗口更窄的容器。组件的 `ResizeObserver` 仍是几何权威；viewport 媒体查询仅用于固定定位的 Settings 面板和会话触控样式。

## Verification

聚焦的 AppFrame 组件测试固定手机轨道、宽版抽屉 owner 属性、背景遮罩与 Escape 关闭、焦点返回、背景 inert、选择 Session 后关闭、隐藏缩放手柄以及详情接管。组装后的 Web 验证在 390×844 和 430×932 下检查关闭状态的会话区、打开的抽屉、Settings 面板以及 document 不出现横向溢出。

## Consequences

手机用户获得完整会话宽度、可读的 Settings 页面、可达的 Session 导航以及全屏工具详情，同时不牺牲宽屏布局依赖的挂载状态保证。代价是 AppFrame 增加第二种展示模式，并存在两个响应式阈值：720px 用于框架所有的栏位，640px 用于固定定位的 Settings 表面。抽屉与面板几何仍必须在真实浏览器中验证，因为 jsdom 布局测试无法表示 CSS grid 自动放置和固定定位包含块。
